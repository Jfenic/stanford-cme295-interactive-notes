/ ¿Cómo aprende y genera un modelo? / How does a language model learn and generate?

00:00:31 – 00:03:11

Un modelo extenso de lenguaje (LLM) aprende a predecir el siguiente token a partir del contexto previo. Durante el preentrenamiento procesa billones de palabras y ajusta sus parámetros para estimar la distribución de probabilidad $P(w_t \mid w_1, \dots, w_{t-1})$ sobre todo el vocabulario $|\mathcal{V}|$. A Large Language Model (LLM) learns to predict the next token given preceding context. During pre-training it processes trillions of words and adjusts its parameters to estimate the probability distribution $P(w_t \mid w_1, \dots, w_{t-1})$ over the vocabulary $|\mathcal{V}|$.

Prerrequisito clave (Clase 1): la tokenización por subpalabras (subword tokenization) divide palabras poco frecuentes en fragmentos con sentido y convierte cada token en un vector (embedding) que se contextualiza mediante autoatención ($Q, K, V$). Key prerequisite (Lecture 1): subword tokenization splits rarer words into meaningful sub-units and maps each token to an embedding vector contextualized via self-attention ($Q, K, V$).

/ Solo Codificador (BERT) vs. Solo Decodificador (GPT) / Encoder-Only (BERT) vs. Decoder-Only (GPT)

00:03:12 – 00:19:17

BERT (2018) Solo Codificador: Atención Bidireccional + Ajuste Fino Encoder-Only: Bidirectional Attention + Fine-Tuning

  • Idea principal (00:04:45): Cada token atiende a tokens a su izquierda y derecha. Añade el token especial [CLS] al inicio para resumir toda la secuencia. Main idea (00:04:45): Every token attends to both left and right context. Prepends a special [CLS] token to aggregate sequence-level representation.
  • 1. Preentrenamiento (costoso, no supervisado): Usa dos tareas sustitutas (proxy tasks): MLM (Masked Language Modeling: ocultar tokens como "A [MASK] teddy bear is [MASK]" y predecirlos) y NSP (Next Sentence Prediction: predecir si la oración B sigue a la A). 1. Pre-training (expensive, self-supervised): Uses two proxy tasks: MLM (Masked Language Modeling: masking tokens like "A [MASK] teddy bear is [MASK]" and predicting them) and NSP (Next Sentence Prediction: classifying if sentence B follows A).
  • 2. Ajuste fino (Fine-tuning, económico): Añade una capa lineal sobre [CLS] para clasificar sentimiento o sobre cada token para entidades (NER). Excelente para embeddings, pero no genera texto fluido. 2. Fine-tuning (inexpensive): Adds a linear head on [CLS] for sentiment classification or on tokens for NER. Great for embeddings, but cannot naturally generate free text.

GPT (2018+) Solo Decodificador: Atención Causal y Paradigma Texto-a-Texto Decoder-Only: Causal Attention & Text-to-Text Paradigm

  • Arquitectura simplificada (00:14:05 y 00:27:55): Conserva solo el decodificador y elimina la atención cruzada (cross-attention). Usa máscara causal ($n \le m$) en toda la secuencia para no filtrar información futura. Simplified architecture (00:14:05 & 00:27:55): Keeps only the decoder and removes cross-attention. Applies a causal mask ($n \le m$) across the entire sequence to prevent future leakage.
  • Unificación texto-a-texto sin ajuste fino obligatorio: Cualquier tarea (clasificación, resumen, traducción) se formula como predecir el siguiente token a partir de una instrucción (prompt). Text-to-text unification without mandatory fine-tuning: Any task (classification, summarization, translation) is framed as autoregressive next-token prediction from a prompt.
$$\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}} + M\right)V, \qquad M_{m,n}^{\text{GPT}} = \begin{cases} 0 & \text{si } n \le m \\ -\infty & \text{si } n > m \end{cases}$$
Error frecuente (00:16:31): Creer que GPT procesa el prompt bidireccionalmente como el codificador de un modelo secuencia-a-secuencia. En un modelo decoder-only estándar, también los tokens del prompt llevan máscara causal. Common mistake (00:16:31): Assuming GPT processes the input prompt bidirectionally like an encoder. In a standard decoder-only model, prompt tokens are also causally masked.

/ Leyes de Escalado (Chinchilla) y Mezcla de Expertos (MoE) / Scaling Laws (Chinchilla) & Sparse Mixture of Experts (MoE)

00:19:22 – 00:44:15

CHINCHILLA (2022) FLOPs vs. FLOP/s y la Regla de 20 Tokens por Parámetro FLOPs vs. FLOP/s and the 20 Tokens per Parameter Rule

  • Notación (00:22:15): FLOPs (s minúscula) = cantidad total de operaciones de coma flotante realizadas ($\sim 10^{25}\text{ FLOPs}$ en un LLM de frontera). FLOP/s (o FLOPS) = operaciones por segundo (velocidad del hardware). Notation (00:22:15): FLOPs (lowercase s) = total floating-point operations executed ($\sim 10^{25}\text{ FLOPs}$ for a frontier LLM). FLOP/s (or FLOPS) = operations per second (hardware throughput).
  • Optimalidad de Chinchilla (00:23:37): Los modelos gigantes previos ($>200\text{B}$) estaban infraentrenados. Con el mismo cómputo $C \approx 6ND$, Chinchilla ($N = 70\,000\text{ millones}$ de parámetros entrenado con $D = 1{,}4\text{ billones}$ [$1{,}4 \times 10^{12}$] de tokens) superó a Gopher ($280\text{B}$). Regla óptima de entrenamiento denso: $D \approx 20N$. Chinchilla optimality (00:23:37): Prior giant models ($>200\text{B}$) were undertrained. For the same compute $C \approx 6ND$, Chinchilla ($N = 70\text{B}$ parameters trained on $D = 1.4\text{ trillion}$ [$1.4 \times 10^{12}$] tokens) beat Gopher ($280\text{B}$). Compute-optimal dense rule: $D \approx 20N$.

SPARSE MoE Expertos Dispersos en la FFN, Colapso y Tendencias 2024–2026 Sparse Experts in FFN, Routing Collapse & 2024–2026 Trends

  • ¿Dónde se ubica? (00:34:13): Sustituye la capa FFN por $N$ subredes expertas y un enrutador (router) lineal por token que evalúa solo el Top-$k$ ($k \ll N$), desacoplando capacidad total de parámetros y FLOPs por token. Where is it placed? (00:34:13): Replaces the FFN layer with $N$ expert subnetworks and a per-token linear router that evaluates only the Top-$k$ ($k \ll N$), decoupling total parameter capacity from per-token FLOPs.
  • Colapso de enrutamiento (Routing collapse, 00:36:25): Los expertos elegidos al principio mejoran más rápido y acaparan todos los tokens («los ricos se vuelven más ricos»). Se corrige sumando una pérdida auxiliar $\mathcal{L}_{\text{aux}}$ con el operador stop_grad sobre la fracción discreta $f_i$. Routing collapse (00:36:25): Early-favored experts improve faster and monopolize all tokens ("rich get richer"). Fixed by adding a load-balancing loss $\mathcal{L}_{\text{aux}}$ using stop_grad on the discrete token fraction $f_i$.
  • Tendencia 2024–2026 (00:40:20): Combinar expertos compartidos (siempre activos) + expertos de grano fino ($N = 256\text{ a }384$ expertos pequeños, activando $k=8$). 2024–2026 trend (00:40:20): Combining always-active shared experts + fine-grained routed experts ($N = 256\text{ to }384$ smaller experts, activating $k=8$).
$$\hat{y}_{\text{MoE}}(x) = \sum_{i \in \mathcal{T}_k(x)} g_i(x) E_i(x), \qquad \mathcal{L}_{\text{aux}} = \alpha \cdot N \sum_{i=1}^{N} \text{stop\_grad}(f_i) \cdot P_i$$

/ Receta Moderna: RoPE, SWA, GQA, Pre-Norm y RMSNorm / Modern Layer Recipe: RoPE, SWA, GQA, Pre-Norm & RMSNorm

00:45:15 – 01:21:05

POSICIÓN De las Agujas del Reloj Sinusoidales a RoPE (00:45:37 – 01:09:20) From Sinusoidal Watch Hands to RoPE (00:45:37 – 01:09:20)

Los vectores sinusoidales codifican la posición usando frecuencias $\omega_i$ como las agujas de un reloj (segundero rápido, horario lento), pero al sumarse al embedding inicial contaminan las capas FFN. RoPE (Rotary Position Embedding) actúa quirúrgicamente dentro de la atención: divide $q_m$ y $k_n$ en pares 2D y los rota un ángulo $m\theta_i$ y $n\theta_i$. Así, el producto escalar $(R_{m\theta} q_m)^\top (R_{n\theta} k_n) = q_m^\top R_{(n-m)\theta} k_n$ depende solo de la distancia relativa $n - m$. Sinusoidal vectors encode position using frequencies $\omega_i$ like watch hands (fast second hand, slow hour hand), but adding them to input embeddings pollutes FFN layers. RoPE (Rotary Position Embedding) acts surgically inside attention: splitting $q_m$ and $k_n$ into 2D pairs and rotating them by $m\theta_i$ and $n\theta_i$. Their dot product $(R_{m\theta} q_m)^\top (R_{n\theta} k_n) = q_m^\top R_{(n-m)\theta} k_n$ depends purely on relative distance $n - m$.

ATENCIÓN Ventana Deslizante (SWA) y Caché KV con GQA (01:09:22 – 01:18:10) Sliding Window (SWA) & KV Cache with GQA (01:09:22 – 01:18:10)

• SWA: Cada token atiende solo a $W$ tokens previos ($O(T \cdot W)$), pero al apilar $L$ capas el campo receptivo efectivo crece hasta $L \times W$.
• GQA (Grouped-Query Attention): Para no recalcular $K$ y $V$ de tokens pasados, se guardan en la caché KV (la consulta $Q$ solo sirve en el paso actual y no se guarda). GQA agrupa las $H_q$ cabezas de consulta en $G$ grupos que comparten una sola proyección $K$ y $V$, reduciendo drásticamente la memoria frente a MHA sin perder la calidad que sacrificaba MQA ($G=1$). • SWA: Each token attends only to $W$ prior tokens ($O(T \cdot W)$), while stacking $L$ layers expands the effective receptive field to $L \times W$.
• GQA (Grouped-Query Attention): To avoid recomputing past $K$ and $V$ tensors, they are stored in the KV cache (query $Q$ is used only at the current step and never cached). GQA groups $H_q$ query heads into $G$ groups sharing one $K, V$ head each, slashing KV memory vs. MHA while preserving accuracy better than MQA ($G=1$).

NORM Pre-Norm y RMSNorm (01:18:11 – 01:21:05) Pre-Norm & RMSNorm (01:18:11 – 01:21:05)

Pre-Norm ($y = x + \text{Subcapa}(\text{Norm}(x))$) deja el camino residual libre de obstáculos para el gradiente. RMSNorm elimina la resta de la media $\mu$ y el sesgo $\beta$ de LayerNorm, reduciendo operaciones con la misma estabilidad. Pre-Norm ($y = x + \text{Sublayer}(\text{Norm}(x))$) keeps the residual stream unobstructed for gradient flow. RMSNorm drops mean $\mu$ subtraction and bias $\beta$ from LayerNorm, cutting compute with equal stability.

$$R_{\Theta, m}^{2\text{D}} = \begin{pmatrix} \cos m\theta_i & -\sin m\theta_i \\ \sin m\theta_i & \cos m\theta_i \end{pmatrix}, \qquad \text{RMSNorm}(x)_j = \frac{x_j}{\sqrt{\frac{1}{d}\sum_{i=1}^{d} x_i^2 + \epsilon}} \cdot \gamma_j$$

DECODIFICACIÓN Greedy, Beam Search, Top-$K$, Top-$P$ e Invarianza al Lote a $T=0$ Greedy, Beam Search, Top-$K$, Top-$P$ & Batch Invariance at $T=0$

  • Deterministas vs. Estocásticos (01:22:20): Greedy (elegir el máximo local) y Beam Search (mantener $k$ haces) son reproducibles (útiles en resúmenes y LLM-as-a-Judge), pero robóticos en chat. El muestreo con Temperatura $T$ + truncamiento Top-$K$ o Top-$P$ (nucleus sampling) aporta fluidez. Deterministic vs. Stochastic (01:22:20): Greedy and Beam Search are reproducible (useful in summarization and LLM-as-a-Judge) but robotic in chat. Sampling with Temperature $T$ + Top-$K$ or Top-$P$ truncation brings natural fluency.
  • ¿Por qué $T=0$ no es $100\%$ determinista en producción? (01:31:00): La suma en coma flotante no es asociativa: $(a+b)+c \neq a+(b+c)$. Cuando un servidor agrupa dinámicamente peticiones de distintos usuarios en lotes (batches), los kernels de GPU cambian el orden de reducción (falta de invarianza al lote o batch invariance), alterando ligeramente los logits. Why is $T=0$ not $100\%$ deterministic in production? (01:31:00): Floating-point addition is non-associative: $(a+b)+c \neq a+(b+c)$. When an inference server dynamically batches user requests, GPU kernels alter reduction orders (lack of batch invariance), slightly shifting logits.
  • Decodificación guiada (Guided decoding, 01:33:45): Para garantizar un JSON $100\%$ válido, se aplica una máscara gramatical en cada paso que fija en $-\infty$ cualquier token que viole el esquema sintáctico (ej. forzar que el primer token empiece por {). Guided decoding (01:33:45): To guarantee $100\%$ valid JSON, a grammar mask sets to $-\infty$ any vocabulary token that violates syntax rules at each step (e.g., forcing the first token to start with {).

CONTEXTO Ventana de Contexto, Context Rot, CoT y Autoconsistencia (01:35:16 – 01:43:05) Context Window, Context Rot, CoT & Self-Consistency (01:35:16 – 01:43:05)

  • Ventana de contexto y Context Rot: Suma entrada + salida generada ($1\text{ token} \approx 3/4\text{ palabra}$, $1\text{ página} \approx 500\text{ tokens}$, $100\text{k} \approx 1\text{ libro}$). En contextos muy largos llenos de ruido se degrada la recuperación de datos («aguja en un pajar» / context rot). Context window & Context Rot: Includes input + generated output ($1\text{ token} \approx 3/4\text{ word}$, $1\text{ page} \approx 500\text{ tokens}$, $100\text{k} \approx 1\text{ book}$). Long, noisy contexts degrade fact retrieval ("needle in a haystack" / context rot).
  • Sin tocar los pesos: Aprendizaje en contexto (few-shot), Cadena de Pensamiento (Chain-of-Thought, CoT) para generar pasos intermedios de razonamiento, y Autoconsistencia (Self-consistency) muestreando múltiples rutas CoT y eligiendo por votación mayoritaria. Weight-free gains: In-context learning (few-shot), Chain-of-Thought (CoT) for intermediate reasoning tokens, and Self-consistency by sampling multiple CoT paths and selecting via majority voting.
